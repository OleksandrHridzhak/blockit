# Швидкий запуск Blockit у dev-режимі

Проєкт використовує npm (`package-lock.json`), Expo SDK 58 та Node з `.nvmrc` (зараз 24). Запускай із кореня проєкту, а не з копії в `outputs/`.

## Звичайний запуск

1. Якщо сервер цього проєкту вже працює, використай його URL. Не запускай другий Metro. Для стандартного порту перевір `http://localhost:8081/status` (Metro відповідає `packager-status:running`); це ще не підтверджує, що сервер належить саме Blockit. Звір робочу папку в його терміналі або команду процесу.
2. Якщо `node_modules/.bin/expo.cmd` вже є і залежності не змінювалися, пропусти встановлення. На чистій копії або після зміни залежностей виконай `npm ci` один раз.
3. Обери один режим нижче. Залиш сервер працювати й повідом користувачу його URL.

### Браузер — швидка перевірка інтерфейсу

```powershell
npm run web -- --localhost --port 8081
```

Відкрий `http://localhost:8081`. Для запуску без мережевих запитів Expo CLI заміни `--localhost` на `--offline`: ці прапорці не можна поєднувати в установленій версії CLI.

### iPhone — уже встановлений development build

```powershell
npm start -- --dev-client --lan --port 8081
```

Телефон і комп’ютер мають бути в одній доступній локальній мережі. Відкрий development build Blockit та QR/посилання, яке показав Expo. `localhost` на телефоні не веде до комп’ютера. TestFlight release не є development client.

Якщо development build ще немає, потрібна окрема нативна збірка з профілем `development`. Не запускай її автоматично для звичайного перегляду UI. На Windows не запускай `npm run ios` для iOS Simulator: він потребує macOS.

## Що зазвичай даремно сповільнює запуск

- Не виконуй `npm ci`, Expo Doctor, lint, тести, export, prebuild чи EAS build перед кожним стартом. Для запиту «запусти проєкт» достатньо перевірити запуск; перевірки коду потрібні після змін коду.
- Не використовуй `--clear` за замовчуванням: зберігай кеш Metro. Очищай його лише за ознак проблем із кешем.
- Не запускай тунель за замовчуванням. Використовуй `--tunnel` лише коли телефон не може підключитися через LAN; не поєднуй із `--offline`.
- Не встановлюй глобальний `expo-cli` і не завантажуй CLI через `npx ...@latest`: npm scripts використовують установлену версію проєкту.
- Не заверши сервер після короткого таймауту інструмента: збережи ID сесії, перевір готовність та залиш процес працювати. Не перечитуй повний лог у циклі.
- Якщо 8081 зайнятий іншим проєктом, використай явно `--port 8082` та повідом новий URL. Не заверши сторонній процес.

## Коли запуск вважається готовим

Для web відкрий сторінку та дочекайся першої компіляції: перевір, що з’явився інтерфейс і немає помилки запуску. Сам відкритий порт цього не доводить. Для iPhone повідом URL/QR Metro; без підключеного телефона не стверджуй, що застосунок на ньому запущено.

Web та Expo Go не перевіряють реальне блокування Screen Time. JS/TS-зміни зазвичай підхоплює Fast Refresh; зміни Swift, нативних модулів, розширень або нативної конфігурації потребують нового development build.
